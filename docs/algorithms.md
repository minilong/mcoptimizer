# 算法详解

本文档展开 README 中三个求解器的技术细节与已声明的取舍。

## 1. budget 模式：券感知的有界背包

**问题**：预算 `B`（分）、`P` 人用餐，在餐品（可重复购买，有上限）与券的组合空间里最大化效用。

### 1.1 券子集枚举（外层）

券分两类：

- `stackable=true`：可自由组合，枚举所有子集（2^n，n 通常 ≤ 3）；
- `stackable=false`（默认）：同单互斥，任一子集至多包含一张。

可行子集数 = `2^stackable × (exclusive + 1)`，实测通常 ≤ 数十。

### 1.2 单位槽展开与效用函数

每件餐品展开为 `max_per_person × P` 个 0/1 单位槽（bounded → 0/1 化）。
`free_item` / `discount_item` 券生成特价槽（价格 0 或特价，限购 1 件）。

效用（可加性是关键，保证 DP 最优子结构）：

```
u_i = w1 · protein_g + w2 · min(kcal, 600)/100 + w3 · satiety(category)
    + main_bonus  (该品属于主食类且是前 P 个槽)
    + drink_bonus (饮品同理)
```

`main/drink_bonus` 把「每人一份主食+一杯饮品」建模为边际递减的软偏好而非硬约束，
避免破坏 DP 结构。权重均可通过 CLI 调整（`--w-protein` 等）。

### 1.3 0/1 背包 DP

- 所有价格与预算先除以 GCD 缩放（菜单价多为 10 的倍数，DP 表缩小 10 倍）；
- `dp[c]` = 恰好花费 c 分的最大效用，回溯取最优；
- 复杂度 `O(slots × B/scale)`，`B=100元` 时为毫秒级。

### 1.4 折扣的后处理（声明的近似）

`threshold_off`（满减）与 `discount_rate`（满折）券、门店促销在 DP 出解后验证应用：
门槛按折前小计判定。**已知局限**：可能漏掉「为凑满减门槛而多买低效用商品」的解；
换来的是 DP 结构干净、每一步可解释。精确建模需把门槛揉进状态（维度爆炸），工程上不值得。

### 1.5 近似 Top-K

DP 只给单一最优。策略：每轮把上一轮方案中数量最多餐品的购买上限减 1 后重解，
强制方案多样性，按效用排序去重取前 K。**这是近似 Top-K**（不保证严格第 2/3 优），
与 nutrition 模式的严格 Top-K 形成对照。

## 2. nutrition 模式：PuLP ILP

**问题**：蛋白质 ≥ X、热量 ≤ Y（可选脂肪 ≤ Z）下，总费用最小。

### 2.1 模型

- 变量：`x_i ∈ {0..cap_i}`（每品数量）；券启用变量 `z_j ∈ {0,1}`；
- 目标：`min Σ price_i·x_i − Σ savings_j·z_j`；
- 特价券：`saving = (price − special)·z`，且 `z ≤ x_item`（买了才能用）；
- 满减券：big-M 线性化 `subtotal ≥ threshold·z`；
- 互斥券组：`Σ z ≤ 1`。

### 2.2 严格 Top-K（integer cut）

求得解 `p` 后，对每个物品引入两个二进制变量
`d_i`（`x_i ≥ p_i+1`）与 `e_i`（`x_i ≤ p_i−1`），加约束 `Σ(d_i+e_i) ≥ 1`
（即「至少一件商品数量不同」），重解即得严格的第 2、3 … 优。

### 2.3 缺失数据处理

无营养数据的餐品默认**排除**（否则 0 蛋白质幽灵会污染解），并输出警告；
`--include-unknown` 可强制包含。

## 3. coupon 模式：DFS + 分支限界

**问题**：心愿单已定的前提下，多张券怎么用最省。

- 搜索空间 = 单品券（free/discount）的启用子集 × 账单券（满减/满折）的启用子集，
  受互斥约束剪枝；
- 单品券作用于一件商品（其余数量按原价）；
- 促销仅在没有用任何券时参与（保守默认 `stackable_with_coupon=false`）；
- 最终金额建议经 mcd-mcp `calculate-price` 权威验价。

## 4. 性价比天梯

`蛋白质/元`、`热量/元`、`饱腹感/元` 三个指标排序。价格为 0（赠品/免费券）时指标为 ∞，
单独成区展示；无营养数据的餐品指标显示 `—` 并排末位。
